# Ainspector 个人 UI 原型设计

分支：`codex/review-ui-prototype`。用户确认中文界面；风险评级保持“未评估”。第一版只读，读取已发布的 2026-09-28 评测快照，不调用模型、不发布 GitHub 评论、不编辑源码。

## 选择与范围

采用独立 `ui/` React + TypeScript + Vite 应用。直接修改静态 HTML 的初始化成本低，但组件和异步数据状态难维护；完整后端与数据库方案能保存操作历史，但本阶段没有该需求。独立应用可分别安装、构建，不改变现有 Bot 的运行方式。

## 页面与视觉

浅色工作台，深蓝导航、克制的蓝色强调、语义化红绿 diff。左侧案例搜索与类别过滤，中间显示实际 patch，右侧显示模型原文及 AI 辅助评分。单模型详情与三模型对照可切换。独立概览页解释样本规模与差异；扩展页说明风险、建议、补丁和撤回的状态边界。窄屏上下排列，按钮有键盘焦点与可访问名称。

## 数据与信任边界

静态数据适配器通过异步接口加载 cases.json、records.json、metrics.json，使用运行时 schema 校验。UI 组件使用领域类型，不直接读文件或服务商响应。未来 HTTP 适配器可替换数据源；该接口本身不承诺已有后端。

旧的评分是 Codex 辅助评分，不标成独立人工评分。LGTM 只表示模型没有提出意见。案例类型是预设标签，不是模型风险结论。评论按真实 hunk 定位到片段末行，标明“定位参考”，不伪称模型精确定位了缺陷。

风险评级以 discriminated union 表达未评估、证据不足、已评估；已评估需要规则版本、证据引用与提交版本。未来应用补丁前检查 base commit、文件哈希和用户确认，保存 before/after；撤回仅在当前内容仍匹配 after 时执行，防止覆盖后续修改。此处只定义接口与流程，不实现修改能力。

## 验证

验证 18 条记录、6 个案例之间的关联与缺失/重复输入；验证 diff 新旧行号、纯删除、多 hunk、无效定位。构建执行 TypeScript 检查。浏览器验证案例筛选、模型切换、对照、空结果、移动端布局和页面控制台。说明数据快照、AI 评分和动态能力尚未实现的边界。
